rnaseq-flow · UCL ARC

First, correctness. A schema can check that a column exists; it can't check what the values mean. So before any process is scheduled the pipeline checks the things that otherwise fail after alignment and quantification have already run, or don't fail at all. The baseline condition decides which way every result points, so a reference level that isn't in the samplesheet stops the run rather than falling back to alphabetical order. Condition, batch and design covariate values have to be valid R names, because DESeq2 builds its coefficient names from them. It also needs two conditions with at least two replicates each, a container engine, and an organism that matches the reference. And since 1.9.0, an analysis you asked for that couldn't run is listed in the report with the reason. The validate-only flag runs all of this and exits, so it can sit in front of any job submission.
