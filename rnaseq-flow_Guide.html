The complete guide

From what bulk RNA-seq measures, through installing Nextflow and configuring a run, to reading every file the pipeline writes. One page, no external dependencies, works offline.

Pipeline 1.8.0 Nextflow ≥ 25.10.0 DSL2 GPL-3.0

1. Introduction

What the data is, what the pipeline does with it, and what Nextflow contributes. Read this if RNA-seq or workflow managers are new to you. Skip to installation if neither is.

The biology #

A cell's genome is fixed, but which genes it transcribes is not. Bulk RNA-seq measures that transcription. RNA is extracted from a sample, converted to cDNA, fragmented, and sequenced. The number of reads falling on a gene is a proxy for how much of that gene's RNA was present.

The word "bulk" matters. Every cell in the sample contributes to one pooled measurement, so what comes out is an average across however many cells went in. A gene that doubles in a rare subpopulation and stays flat elsewhere looks almost unchanged. Single-cell RNA-seq exists to answer that question; this pipeline does not, and no amount of depth will make bulk data resolve it.

Two properties of the raw counts shape everything downstream. They are compositional: a fixed number of reads is divided among all transcripts, so a gene can appear to fall simply because another gene rose and took up more of the pool. And their variance grows with their mean, which rules out methods that assume constant variance. DESeq2 and edgeR exist to handle both, modelling counts as negative binomial and normalising for library size and composition. This is why raw integer counts must reach them: handing them TPM or FPKM destroys the information the model depends on.

Library preparation decides what you can ask

Poly-A selection captures polyadenylated transcripts, which is most mRNA and little else. Ribosomal depletion keeps non-polyadenylated species, including many lncRNAs and histone mRNAs, at the cost of a noisier library. If your library is rRNA-depleted and you quantify against Ensembl's cDNA file alone, lncRNAs go uncounted because they were never in the index. Add the ncrna.fa.gz file for that species.

Stranded kits record which strand the original RNA came from, which resolves reads falling in overlapping genes on opposite strands. Most current kits (TruSeq Stranded mRNA and other dUTP protocols) are reverse-stranded. Getting this setting wrong roughly halves the counts, which is why the pipeline measures it rather than assuming (strandedness).

Designing the experiment #

The analysis cannot rescue a design. Four decisions are worth making deliberately before any sequencing happens.

Replicates

Biological replicates, meaning independent samples, not the same library sequenced twice. The pipeline enforces a minimum of two conditions and two replicates each because DESeq2 and edgeR cannot estimate dispersion below that. Three or more is where the estimates become trustworthy, and rMATS flags designs below three.

Depth

For differential expression of moderately expressed genes, 20 to 30 million reads per sample is a common working figure. More replicates beat more depth for detecting differential expression. Splicing and transcript-level work need more, since the evidence is junction reads rather than whole genes.

Confounds

If every control was processed on Monday and every treated sample on Friday, batch and condition are confounded and no model can separate them. Randomise sample processing across batches. If a batch exists anyway, record it and model it (covariates).

The baseline

One condition is the denominator of every contrast, so it decides which way every fold change points. Name the control group REF, or pass --reference_level. Getting this wrong produces a complete, plausible set of results pointing the wrong way (more).

What the pipeline does #

rnaseq-flow takes FASTQ files to interpreted results. You choose the aligner, choose which stages run, and supply references directly or let the helper workflows fetch and index them.

  1. Read QC and trimming FastQC on the raw reads, then fastp for adapter and quality trimming.
  2. Alignment or quantification STAR or HISAT2 align to the genome and produce sorted, indexed BAMs. Salmon or Kallisto quantify against the transcriptome without producing alignments.
  3. Post-alignment QC Genome aligners only. RSeQC measures strandedness, read distribution and gene-body coverage; deepTools writes CPM-normalised BigWig tracks.
  4. Gene-level counts featureCounts for the genome routes, or tximport summarising transcript quantification to gene level for the pseudo-aligners.
  5. Differential expression DESeq2 and edgeR both run, in parallel, on the same counts. They are two independent callers, not a chain: neither feeds the other.
  6. Splicing, isoforms and fusions rMATS event-level splicing, DEXSeq transcript usage, edgeR diffSpliceDGE feature usage, IsoformSwitchAnalyzeR, and STAR-Fusion. Each is gated on the aligner and on an opt-in flag.
  7. Functional enrichment fgsea on the ranked DESeq2 list, gprofiler2 on the thresholded one.
  8. Reporting MultiQC for run-wide QC, and an interactive Quarto report that pulls the whole run into one document.
Enrichment reads DESeq2 only

GSEA and gProfiler consume the DESeq2 results. The edgeR tables are an independent cross-check and are not used downstream. Genes called significant by both callers are the high-confidence set.

Every differential-expression table carries gene_id, gene_name and gene_biotype parsed from the GTF, so results are readable without a separate identifier lookup. Every figure is written as SVG and as 300 dpi PNG, and each analysis directory carries a reproduce/ folder that redraws its figures from the results alone (section 6.11).

Nextflow, briefly #

Nextflow is the workflow manager underneath. You do not need to write any to use the pipeline, but four of its ideas explain most of what you will see on screen.

IdeaWhat it means in practice
Processes One step, such as STAR_ALIGN. Each declares its own container, so you never install STAR, Salmon or R yourself.
Channels The queues connecting processes. A per-sample channel carries one item per sample, so a process declared once runs six times for six samples, in parallel, without a loop anywhere.
The work directory Every task runs in its own hashed folder under work/, with its inputs symlinked in. Results you asked for are published to --outdir; work/ holds everything else and can be deleted once a run is finished with.
Resume -resume reuses any task whose inputs and code are unchanged. Fix a parameter that affects the last stage and only that stage reruns.

Two conventions catch people out. Nextflow's own options take a single dash (-profile, -resume, -c); the pipeline's own parameters take two (--input, --aligner). And a run is orchestrated by a head process that must stay alive for the duration, which is why cluster runs belong inside screen or tmux.

Check it works #

Three checks, in increasing cost. None of them needs real data.

Print every parameter

nextflow run main.nf --help

Prints every parameter, grouped, with its default, read from nextflow_schema.json. The same schema validates parameters on every run, so a typo such as --alinger star aborts immediately rather than being silently ignored.

Dry-run the whole graph

nextflow run main.nf --input samplesheet_test.csv --aligner star \
    --star_index fake --gtf fake.gtf -stub-run

Every process ships a stub block that creates placeholder outputs. -stub-run executes those instead of the real tools, so the whole channel topology is exercised in seconds with no containers and no data. This is the check to run after editing the pipeline.

Validate a real samplesheet

nextflow run main.nf --input samplesheet.csv --aligner star \
    --star_index /path/to/star_index --gtf /path/to/genes.gtf \
    --validate_only
Samplesheet OK: 6 sample(s), 2 condition(s) [REF:3, NaCl:3]
--validate_only: inputs are valid. No processes were run.

It runs exactly the validation a real run performs, so there is no second set of rules to drift out of step, and it reports every problem at once rather than stopping at the first:

Samplesheet validation failed (2 problem(s)):
  - row 3: duplicate sample id 'ctrl_1'
  - row 4 (sample 't1'): R1 file not found: reads/MISSING_1.fq.gz

It exits non-zero on failure, so it gates a script:

nextflow run main.nf --input samplesheet.csv ... --validate_only && sbatch run_real.sh
Worth the few seconds before a cluster submission

A mistyped path discovered by --validate_only costs seconds. The same typo discovered by a scheduler costs a queue wait. Two things the flag does not do: a file-glob input has no sample or condition column so there is nothing to validate beyond read pairing, and it has no effect with --download_refs or --build_indices, where it warns rather than passing silently.

3. Configuration

The profile, the samplesheet and the parameters. Most runs need a profile, an aligner, an index, a GTF and a samplesheet; everything else has a working default.

Profiles #

Every command needs a -profile

It tells Nextflow how to obtain and run the software for each process. Without one, the pipeline expects the tools to already be on your PATH, and they will not be.

ProfileUse it when
dockerRunning locally with Docker. The usual choice on a laptop or workstation.
singularityShared or HPC infrastructure, where Docker is normally unavailable.
condaNo container engine at all. Slower, and environments are solved at run time, which needs network access.
sgeSubmitting to an SGE cluster (UCL Myriad, Kathleen, Young). Enables Singularity itself, so use it alone.
test_yeastThe small S. cerevisiae test dataset. Caps CPU and memory to laptop scale. Combine with an engine.
treNo internet access: a Trusted Research Environment or air-gapped HPC. Needs the offline bundle (section 3.8).

Combine with a comma. The engine and the environment are separate choices:

-profile docker                 # local run
-profile test_yeast,docker      # the test dataset, locally
-profile sge                    # UCL cluster (Singularity already enabled)
-profile tre,sge                # air-gapped cluster

The samplesheet #

--input takes a CSV with at least four columns.

sample,R1,R2,condition
ctrl_rep1,data/ctrl_rep1_R1.fastq.gz,data/ctrl_rep1_R2.fastq.gz,REF
ctrl_rep2,data/ctrl_rep2_R1.fastq.gz,data/ctrl_rep2_R2.fastq.gz,REF
treat_rep1,data/treat_rep1_R1.fastq.gz,data/treat_rep1_R2.fastq.gz,treatment
treat_rep2,data/treat_rep2_R1.fastq.gz,data/treat_rep2_R2.fastq.gz,treatment
ColumnDescription
sampleUnique identifier. Names every output file for that sample.
R1Path to the R1 (or single-end) FASTQ. Absolute, or relative to the launch directory.
R2Path to the R2 FASTQ. Leave empty for single-end data; layout is detected from whether this is present.
conditionExperimental group. Drives the differential-expression design.
batch (optional) Batch or covariate label. If present, the DE model becomes ~ batch + condition automatically.

The samplesheet is validated before any work starts, and the run aborts immediately if there is a problem. The checks are: required columns present, sample ids unique and non-empty, every R1 and R2 path resolving on disk, at least two conditions, at least two replicates per condition, and every --design variable being a real column. With --stop_at preQC or postQC, where no differential expression runs, the condition and replicate rules are downgraded to warnings.

The baseline condition #

This decides which way every result points

One condition is the denominator of every contrast. A positive log2FoldChange means "up relative to the baseline", and the same holds for the PSI differences rMATS reports. It defaults to a condition literally named REF.

Name your control group REF, or point --reference_level at whatever you called it:

nextflow run main.nf --input samplesheet.csv --aligner star \
    --star_index /path/to/star_index --gtf /path/to/genes.gtf \
    --reference_level Untreated \
    --outdir results -profile docker

With --reference_level Untreated and a Treated group you get Treated_vs_Untreated, and:

ResultA positive value means
log2FoldChange (DESeq2), logFC (edgeR)Higher expression in Treated
IncLevelDifference (rMATS)Higher inclusion in Treated

The setting reaches DESeq2, edgeR, rMATS, DEXSeq and edgeR diffSplice, so every contrast in the run is oriented the same way. It is recorded in pipeline_info/run_manifest.json and shown as Baseline in the analysis report, so a reader of the report alone can tell what the numbers are relative to.

A level you name must exist in the samplesheet

The run stops at launch if it does not, listing the conditions it found. A mistyped baseline would otherwise produce a complete, plausible set of results oriented against the wrong condition. If you name nothing and no group is called REF, conditions are ordered alphabetically, the direction is arbitrary, and each tool says so in the log.

Batch effects and covariates #

The gene-level model defaults to ~ condition. There are two ways to adjust for a confounder.

The quick way is a batch column. The pipeline detects it and the model becomes ~ batch + condition for both DESeq2 and edgeR:

sample,R1,R2,condition,batch
ctrl_1,/data/ctrl_1_R1.fastq.gz,/data/ctrl_1_R2.fastq.gz,REF,b1
ctrl_2,/data/ctrl_2_R1.fastq.gz,/data/ctrl_2_R2.fastq.gz,REF,b2
treat_1,/data/treat_1_R1.fastq.gz,/data/treat_1_R2.fastq.gz,treatment,b1
treat_2,/data/treat_2_R1.fastq.gz,/data/treat_2_R2.fastq.gz,treatment,b2

For full control, pass a formula with --design, for example --design "~ sex + batch + condition". Every variable must be a samplesheet column, and condition must be included since it stays the term being contrasted. An explicit --design overrides the automatic batch behaviour.

Avoid full confounding

A covariate perfectly aligned with condition, such as every REF sample in one batch and every treated sample in another, makes the model rank-deficient and DESeq2 and edgeR abort. --design covers the gene-level tests only: rMATS, DTU and diffSplice keep their own designs.

Strandedness #

--strandedness sets the library strand setting for featureCounts (the genome aligners) and for kallisto.

SettingBehaviour
auto (default) STAR and HISAT2: RSeQC infer_experiment measures every sample and the verdict is fed straight into that sample's featureCounts run. Kallisto: no BAM exists to inspect, so it runs library-type-agnostic.
unstrandedfeatureCounts -s 0, no kallisto strand flag.
reversefeatureCounts -s 2, kallisto --rf-stranded. TruSeq Stranded mRNA and most dUTP kits.
forwardfeatureCounts -s 1, kallisto --fr-stranded. Ligation-based and some older kits.

Each sample's verdict is written to results/rseqc/<sample>.strandedness.txt. Set --strandedness explicitly only to override the inference, and check it against that file if you do, since a wrong strand setting roughly halves your gene counts.

Salmon auto-detects library type internally with --libType A, so it needs no setting. Kallisto has no equivalent and produces no BAM, so it cannot auto-detect: pass forward or reverse explicitly for a stranded library. The pipeline logs a warning when kallisto runs with auto.

Resources and clusters #

Per-process CPU, memory and time come from conf/base.config, keyed off process labels (process_low, process_medium, process_high), and are capped by the three --max_* parameters. A failed task is retried once with doubled memory and time. STAR genome indexing of a mammalian genome needs about 38 GB, so make sure --max_memory allows it.

Running on SGE

conf/sge.config targets the UCL Research Computing clusters. Use it alone, since it already enables Singularity:

nextflow run main.nf -profile sge \
    --input samplesheet.csv --aligner star \
    --star_index /path/to/star_index --gtf /path/to/genes.gtf \
    --outdir results

Run it from a login node inside screen or tmux, or as a small submitted job, so the Nextflow head process survives your session while the work runs on compute nodes. The profile requests memory per core in the form SGE expects, requests node-local scratch, routes any job needing more than a standard node's 4.4 GB per core to the high-memory nodes, and points the Apptainer cache at $HOME/Scratch.

For a different scheduler, copy conf/sge.config as a starting point, or pass a minimal executor block with -c:

process.executor = 'slurm'
process.queue    = 'normal'

HISAT2 index memory, and when it silently degrades

A splice-aware HISAT2 index (hisat2-build --ss --exon) is built from the splice sites and exons in the GTF, and peak memory is driven by that graph rather than by the genome. The pipeline estimates it from the GTF:

memory = 8 GB + 45 GB per GB of uncompressed GTF
Species (Ensembl 116)GTF (gz)Estimated requirement
Human GRCh38135 MB~204 GB
Mouse GRCm39103 MB~158 GB
Zebrafish GRCz1117 MB~34 GB
C. elegans / fly7–8 MB~15–16 GB
Yeast R640.6 MB~9 GB
Check for this warning on any mammalian HISAT2 build

If --max_memory is below the estimate, HISAT2_BUILD does not fail. It drops --ss and --exon and builds a non-splice-aware index instead, which is deliberate (an under-provisioned run produces a usable index rather than being killed) but easy to miss in a long log. The resulting index is not equivalent.

WARN  [HISAT2_BUILD] Only 128 GB available but ~204 GB is needed to build a
  splice-aware index from Homo_sapiens.GRCh38.116.gtf.gz.
  Building WITHOUT --ss/--exon. HISAT2 still aligns across junctions using its
  own model, but sensitivity to novel junctions is reduced.

To force the splice-aware build, raise the ceiling and make sure a node that large exists. --hisat2_build_memory overrides the estimate directly. This affects index building only: alignment is unaffected, and building once on a high-memory machine then reusing the index with --hisat2_index avoids the problem entirely. Under -profile sge it is handled for you, since HISAT2_BUILD is exempted from the standard-node ceiling and any job above 4.4 GB per core gets the high-memory node selector appended.

Running offline (TRE and air-gapped) #

The pipeline does not run as-is without internet access

Nextflow Wave provisions several containers on the fly by contacting an external service at run time. Nothing about that can be tuned: it has to be switched off, and every image supplied locally.

A prepared bundle of every container is published on Zenodo at doi.org/10.5281/zenodo.21880328, a concept DOI resolving to the most recent bundle. It holds 27 Singularity images (about 7 GB), a tre.config profile and a README. Download it outside the TRE, verify it, transfer it in, then:

sha256sum -c rnaseq-flow-1.8.0-singularity.tar.sha256
tar -xf rnaseq-flow-1.8.0-singularity.tar
export NXF_SINGULARITY_CACHEDIR=$PWD/singularity-1.8.0

nextflow run main.nf -c $NXF_SINGULARITY_CACHEDIR/tre.config \
    -profile tre,sge \
    --input samplesheet.csv --aligner star \
    --star_index /path/to/star_index --gtf /path/to/genes.gtf \
    --outdir results

The tre profile disables Wave and pins the seven Conda-declared processes (DESeq2, edgeR/tximport, DEXSeq, GSEA, gProfiler, --download_gmt and the Quarto report) to the bundled images. Combine it with whichever executor profile you need.

  • The bundle is pinned to a release, and v1.8.0 is the current one. Its README.txt records the exact commit it was built from if you need to check. Earlier bundles do not work with this release: v1.8.0 derives the transcriptome from the GTF and added gffread, and v1.7.0 before it moved every Bioconductor package to release 3.22, so both the container references and the Conda specs have changed twice. A mismatch surfaces as a process failing to find its image, not as a clear version error.
  • It also carries the nf-prov plugin, which the RO-Crate needs. Copy it into place and set offline mode, or the run fails with no network to fetch it: 
    cp -r $NXF_SINGULARITY_CACHEDIR/plugins/nf-prov-1.7.0 ~/.nextflow/plugins/
export NXF_OFFLINE=true
    It has to be ~/.nextflow/plugins. Pointing NXF_PLUGINS_DIR at the bundle makes Nextflow report "No plugins" and carry on, so the crate goes silently missing.
  • References and gene sets are separate. The bundle carries software, not data. Run --download_refs and --download_gmt outside the TRE and transfer the reference directory in, keeping reference_metadata.json with those files.
  • Do not use -profile conda in a TRE. It resolves and installs environments at run time, which needs reachable channels. The containers exist precisely to avoid that.

Credit and provenance: edit this before your first run #

Every run writes pipeline_info/run_manifest.json, recording how it was configured, what it ran against, and who did it. That last part is the one thing the pipeline cannot work out for itself, and it is where your contribution to the analysis is captured. Left unset it records whichever account launched the job, credits nobody, and says so.

Nothing in the cloned repository needs editing

Your identity belongs in your own Nextflow config, not in the pipeline. Create or open $HOME/.nextflow/config, which Nextflow reads on every run from any directory.

params.run_contributors = [[
    name        : 'Jane Doe',
    orcid       : '0000-0002-1825-0097',
    roles       : ['formal-analysis', 'data-curation'],
    affiliation : 'https://ror.org/02jx3x895',
    facility    : 'UCL Genomics',
    facility_id : 'RRID:SCR_000000'
]]

Only name is required. The rest are persistent identifiers wherever one exists, so the record resolves rather than merely asserting:

FieldWhat it takes
orcidYour ORCID, bare or as a full URL. Stored as the URL
rolesCRediT contributor roles (ANSI/NISO Z39.104-2022) as lowercase hyphenated tokens. Checked against the standard's fourteen values at launch, then stored as resolvable credit.niso.org/contributor-roles/ URIs
affiliationA ROR identifier for your institution
facility, facility_idA core facility's name, and its RRID where it has one. Most facilities have no ROR of their own

The fourteen valid role tokens. For a pipeline run the realistic ones are formal-analysis, data-curation, software, validation and visualization:

conceptualization        funding-acquisition      resources
data-curation            investigation            software
formal-analysis          methodology              supervision
project-administration   validation               visualization
writing-original-draft   writing-review-editing

A token outside that set stops the run before any process is scheduled, listing every problem at once. That is deliberate: a misspelled role would otherwise produce metadata claiming conformance to a standard for a role that does not exist, and nothing downstream would catch it.

For several people with different roles, or for a shared service account where the attribution should belong to the project rather than to the login, put the same block in a nextflow.config in the directory you launch from. A launch-directory config outranks your home one.

params.run_contributors = [
    [ name: 'Jane Doe',     orcid: '0000-0002-1825-0097',
      roles: ['formal-analysis', 'software'] ],
    [ name: 'A Supervisor', orcid: '0000-0001-5598-6274',
      roles: ['supervision', 'funding-acquisition'] ]
]

For a single run, or to override either file, --run_by "Jane Doe" --run_by_orcid 0000-0002-1825-0097 works on the command line. Identify yourself that way without stating roles and you are credited with formal-analysis, since that is what running the pipeline is, recorded as inferred rather than claimed.

Credit is recorded, never guessed

The pipeline will not decide you deserve a role because a process ran under your login. With nothing set it records the launching account's user name, assigns no roles, and marks source as system_user. A record naming the wrong analyst is worse than no record: it is a false attribution that outlives the run and cannot afterwards be told apart from a true one. Two fields exist for a reader to check before trusting an attribution, source and roles_declared.

The run's contributors answer who did the work. A separate block answers what the work was part of, and it is the level at which a funder, a data owner and a project identifier belong. It changes rarely, so put it in a nextflow.config beside the data rather than in your home config:

params.project = [
    name              : 'Yeast osmotic stress response',
    raid              : '10.12345/abc123',
    rights_holder     : '0000-0001-5598-6274',
    rights_holder_name: 'Nicholas Owen',
    funder            : 'https://ror.org/03x94j517',
    funder_name       : 'Medical Research Council',
    grant             : 'MR/X000000/1'
]
FieldWhat it takes
raidA RAiD (ISO 23527:2022), the persistent identifier for a research activity. RAiDs are DataCite DOIs, so 10.12345/abc123 and https://raid.org/10.12345/abc123 name the same project and either resolves through doi.org too
funderA ROR identifier. RAiD is explicitly not for organisations or grants, so the funder and the grant reference are recorded separately
rights_holderWho owns the data: an ORCID for a person, a ROR for an organisation, or a plain name
grantThe grant reference as the funder writes it
funder_name, rights_holder_nameDisplay names. An identifier resolves but reads as nine characters of hex, so the report shows the name and links the identifier behind it. Either works without its identifier

The RO-Crate

Everything above goes into pipeline_info/run_manifest.json, which only this pipeline's readers understand. Every run also writes ro-crate-metadata.json at the top of the output directory, a Workflow Run RO-Crate: standard JSON-LD that WorkflowHub, repositories and other tools read. It is on by default, because provenance that has to be remembered is not provenance. --ro_crate false turns it off.

Nothing to run afterwards

The crate is finished before the pipeline exits, and the console says what went into it:

RO-Crate: 871 entities, 140 files hashed, 6 result folders expanded
          (175 files), 1 contributor(s), project, 3 input copies removed
          (1.0 MB), 4 workflow files moved to .crate/

Two pieces produce it. The nf-prov plugin writes the execution graph, one CreateAction per task with its inputs, outputs and timings. lib/CrateEnricher.groovy then adds what the plugin has no slot for, reading it from the run manifest: sha256, contentSize and dateModified on every published file; hasPart on the result folders the plugin leaves as bare names; every contributor as a Person behind Role entities carrying CRediT URIs; and the project with its RAiD, funder and rights holder.

It also removes the copies nf-prov makes of your input files. No specification asks for those, and a human GTF is tens of megabytes duplicated into every results directory; the entities become absolute file: references instead, exactly as the plugin already does for the aligner index.

Launch by name for a crate that travels

Running nextflow run main.nf leaves the crate without a repository URL and warns about it. nextflow run nicholas-owen/rnaseq-flow records it, which matters once the crate leaves the machine that made it.

Every identifier is checked at launch and the run stops on a malformed one, for the same reason a bad CRediT token does. An identifier that does not resolve is worse than an absent one: it reads as provenance while pointing nowhere, and a reader cannot tell it from a good one without trying it.

RAiD is not yet uniformly available

The ARDC is the registration authority for Australia and New Zealand, SURF covers Europe, and elsewhere is arranged with the ARDC directly, so check whether your institution can mint one before planning around it. Every other field in the block works without it.

Note that rights_holder is deliberately not a CRediT role. CRediT describes contributions to a piece of work; owning the data is a rights relation over it. Someone who owns the data and also did some of the work gets both: ownership here, roles in run_contributors.

Three claims end up in that one record and they are not interchangeable. Who wrote the pipeline comes from the manifest scope in nextflow.config and does not change between runs. So does the licence the results carry. Who did this analysis is run_contributors. Edit the manifest scope only if you have forked the pipeline and are changing it: running it does not make you its author.

What else the manifest records without any setup: the pipeline version and commit, the full command line, the aligner and quantification route, the baseline condition that fixes the direction of every fold change, the design, the samples per condition, any requested analysis that was skipped, and the reference set with its Ensembl release and SHA-256 where --download_refs fetched it. Keep reference_metadata.json beside your reference files, or that last part reads as not recorded.

main.nf has a single entry point that dispatches to one of three workflows based on the flags you pass. Only one mode runs per invocation.

Mode 1: download references #

Fetches the genome FASTA, the GTF and the cDNA transcriptome for any Ensembl species. All three are guaranteed to describe the same assembly: the download fails rather than mixing them.

nextflow run main.nf \
    --download_refs \
    --download_species homo_sapiens \
    --download_source ensembl \
    --download_release 102 \
    --download_gmt \
    --organism hsapiens \

    -profile docker

With --download_release set, files land in a v<release> subfolder so each Ensembl build stays separate:

references/human/
├── v102/                                             # pinned Ensembl release 102
│   ├── Homo_sapiens.GRCh38.dna.primary_assembly.fa.gz   # genome FASTA
│   ├── Homo_sapiens.GRCh38.102.gtf.gz                   # annotation (note the .102.)
│   ├── Homo_sapiens.GRCh38.cdna.all.fa.gz               # transcriptome (--transcript_fasta)
│   ├── download_log.txt                                 # provenance log (human-readable)
│   └── reference_metadata.json                          # provenance record (machine-readable)

    └── c5_go.gmt        c5_go_bp.gmt
Keep reference_metadata.json with the references

It records source, requested and resolved release, assembly, annotation version, and each file's URL, size and SHA-256. The download is the only moment some of this can be known: an Ensembl GTF's header gives the assembly and genebuild date but never the release it was published in, and the trailing number in its filename is an annotation version rather than the release (release 116 ships Saccharomyces_cerevisiae.R64-1-1.63.gtf.gz). Delete the file and that is unrecoverable.

--download_gmt needs outbound HTTPS

From msigdbr 24 the gene sets are fetched over HTTPS on first use rather than bundled in the package, so this step fails on a compute node with no outbound route. Run the download workflow somewhere with internet access, then pass the resulting file with --gmt on later runs.

Ensembl publishes several annotations per species (abinitio, chr, chr_patch_hapl_scaff, and the canonical one). Only the canonical GTF describes the dna.primary_assembly genome. The pipeline selects the GTF and transcriptome by the assembly named in the genome FASTA and fails loudly rather than guessing. Reference sets downloaded before v1.2.0 used the patch/haplotype GTF and should be re-downloaded.

Starting from a count matrix #

If you already have a gene count matrix, from a previous run, a collaborator or a public dataset, you can skip QC and alignment and enter directly at differential expression. DESeq2, edgeR, GSEA, gProfiler and the analysis report all run as normal.

nextflow run main.nf \
    --input samplesheet.csv \
    --counts counts.tsv \
    --gtf references/human/annotation.gtf \
    -profile docker

--input is still required: the samplesheet supplies condition and any covariates. The R1 and R2 columns are optional and ignored, so a minimal samplesheet is just:

sample,condition
ctrl_1,REF
ctrl_2,REF
treat_1,treatment
treat_2,treatment

--gtf is also required, so results carry gene symbols and biotypes rather than bare identifiers. The run reports the fraction of matrix genes it could annotate and aborts if that fraction is implausibly low, which is the signature of a matrix and GTF from different genome builds.

Two layouts are accepted and auto-detected. A featureCounts wide table, where the Geneid, Chr, Start, End, Strand, Length annotation columns are dropped and the rest are samples. Or a plain matrix with gene IDs in the first column and one column per sample, tab- or comma-delimited. The matrix may be gzipped, the delimiter is auto-detected, and a gene-ID column with no header is handled. Column order does not matter, since columns are reordered to the samplesheet.

Raw integer counts only

Normalised values (TPM, FPKM/RPKM, DESeq2- or CPM-normalised) are rejected, because DESeq2 and edgeR require raw counts. Salmon and Kallisto estimated gene counts as a flat matrix are rejected too: they are non-integer and they lose the transcript-length offsets that length-aware DE needs. Re-run those through the pseudo-aligner instead. Matrices keyed by Entrez or RefSeq identifiers cannot be annotated from a GTF and fail the annotation-match check: map them to Ensembl gene IDs or symbols first.

Splicing, DTU, isoform-switch and fusion analyses need reads or BAMs and cannot run from a count matrix.

Resuming a run #

nextflow run main.nf --input samplesheet.csv ... -profile docker -resume

Any task whose inputs, parameters and code are unchanged is reused from the cache in work/. Change a parameter that only affects enrichment and alignment is not repeated. The cache lives in work/, so do not delete it until you are finished with the run.

Why --strandedness unstranded on three of the four

The default auto infers strandedness with RSeQC, which needs a BAM. Salmon and Kallisto produce none. This dataset is unstranded, so stating it explicitly is both correct and quieter. STAR is left on auto so the inference path itself gets exercised at least once.

What to check

  • results_*/multiqc/rnaseq-flow_multiqc_report.html: every sample should appear under FastQC, fastp and the modules for the route you ran. Kallisto has no MultiQC module, so that run shows only FastQC and fastp.
  • results_*/quarto_report/analysis_report.html: PCA should separate YPD from NaCl, and the volcano plots should be populated.
  • results_*/deseq2_output/deseq2_results_NaCl_vs_REF.csv: this is a salt-stress response, so the usual osmotic-stress genes (GRE2, HSP12, CTT1, STL1) are a reasonable sanity check for the up-regulated set.
  • HISAT2 only: the per-sample overall alignment rate in results_hisat2/hisat2/*.summary.log should be around 96 to 98 percent on this data.
Use c5_go_bp.gmt, not hallmark.gmt, for yeast

Hallmark is 50 human-defined sets; projected onto yeast orthologs, few retain enough genes to test, so hallmark can produce an empty GSEA step that looks like a failure. These are not yeast-native gene sets either: msigdbr maps the human MSigDB collections by orthology. That is fine for exercising the step, which is what the test dataset is for, but a weak basis for biology. For yeast GSEA meant to be interpreted, build a GMT from SGD's own GO annotations.

Do the routes agree? #

Running more than one route is the cheapest real test of the pipeline, because the four are independent implementations that should reach the same biology. Observed on this dataset at 1 M read pairs, DESeq2, padj < 0.05 and |log2FC| > 1:

RouteGenes testedSignificantUpDown
STAR5579852152700
HISAT25773833132701
Salmon5510778130648
Kallisto5961866146720

668 genes were called significant by all four, every pairwise overlap was at least 83 percent of the smaller set, and all four reproduced the same strong down-regulation bias. The overlaps do not split cleanly along the genome-aligner and pseudo-aligner line: STAR agreed more closely with Salmon than with HISAT2 here. That is not in itself a fault, since the routes differ in multimapper handling and length correction.

Those are the DESeq2 calls. edgeR on the same data is consistently a little more generous, having gained power in version 4.x: 924, 951, 893 and 964 significant for STAR, HISAT2, Salmon and Kallisto, 722 called by all four, every pairwise overlap at or above 84 percent. The direction of the bias is the same.

A shape to match, not targets to hit

These numbers come from a subsample drawn by seqtk sample -s42. The seed is fixed, so seqtk users at the default depth should land close to the table, but you will not match it if seqtk was missing when you fetched (the script falls back to the first N reads and says so), if you passed a different read count, or if container versions have moved. What matters is the agreement between routes, not the absolute counts.

Reading order #

  1. quarto_report/analysis_report.html, the Run overview: what was run, on what, against which reference and baseline. Read this first if the results directory is not your own.
  2. multiqc/rnaseq-flow_multiqc_report.html: one page for whole-run QC.
  3. Alignment logs: confirm mapping rates are acceptable.
  4. rseqc/: confirm strandedness and library quality.
  5. deseq2_output/pca_plot.svg: do samples group by condition?
  6. The DE tables, then enrichment, splicing and fusions.

Read and alignment QC #

fastqc/ and fastp/

Check per-base quality (it should stay in the green), adapter content and duplication. Raw RNA-seq normally shows some duplication and a biased first 12 bases or so. That is expected. The fastp report shows reads before and after filtering; a large drop in read count means aggressive filtering, so inspect the input quality.

star/ or hisat2/

The key line in the STAR Log.final.out is Uniquely mapped reads %:

Uniquely mappedInterpretation
> 85%Excellent
70 to 85%Acceptable
< 70%Investigate: contamination, wrong genome, or poor quality

Also watch % of reads mapped to multiple loci, where high values suggest rRNA or repetitive contamination, and % of reads unmapped: too short, which is often an adapter or quality problem.

rseqc/

FileWhat it tells you
*.infer_experiment.txtLibrary strandedness, measured empirically
*.strandedness.txtThe one-word verdict derived from it
*.read_distribution.txtFraction of reads in CDS, UTR, intron, intergenic
*.geneBodyCoverage.txt and .curves.pdf5' to 3' coverage evenness

In infer_experiment.txt, both fractions near 0.5 means unstranded, a "++,--" fraction near 1.0 means forward, and a "+-,-+" fraction near 1.0 means reverse. Most tags in read_distribution.txt should fall in exonic regions; a high intronic or intergenic fraction suggests DNA contamination or incomplete annotation. Gene-body coverage should be a flat plateau, where a strong 3' skew indicates RNA degradation.

Gene counts #

For STAR and HISAT2, featurecounts/<sample>.featureCounts.txt holds gene-level counts, and the .summary file beside it breaks down assigned against unassigned reads and why.

For Salmon and Kallisto, tximport/tximport_gene_counts.csv is the gene-by-sample matrix obtained by summarising transcript quantification to gene level. txi.rds is the full tximport object, which DESeq2 imports with DESeqDataSetFromTximport and edgeR imports as a length offset, giving more accurate normalisation than counts alone.

These counts are not normalised for library size

Do not compare them directly between samples. That is what DESeq2 and edgeR are for.

Differential expression #

DESeq2 and edgeR both run, in parallel, on the same gene counts as two independent callers. One results CSV per pairwise contrast, named deseq2_results_<A>_vs_<B>.csv where B is the baseline and the fold change is A relative to B.

pvalueRaw p-value
padjBenjamini-Hochberg adjusted p-value (FDR). Use this one

The fold change is shrunk with the apeglm estimator, which pulls low-count, high-variance genes toward zero and gives cleaner MA and volcano plots. Shrinkage changes only the effect size: stat, pvalue and padj come from the unshrunken Wald test, so significance calling is unaffected.

A common threshold is padj < 0.05 with |log2FoldChange| > 1, a two-fold change. padj may be NA when DESeq2 filters a gene for low counts or flags it as an outlier, which is normal.

edger_output/

Columns are logFC, logCPM, F, PValue and FDR, with the same three annotation columns. Use FDR. mds_plot is edgeR's sample-similarity plot, analogous to the PCA.

Genes called by both callers are the robust set

Modest disagreement near the significance threshold is expected. The edgeR results are an independent cross-check and are not consumed by any later step.

Every figure is written twice, as .svg for publication and figure assembly and as a 300 dpi .png for slides and email.

Functional enrichment #

gsea_output/

fgsea runs on the ranked DESeq2 gene list for each contrast, genes ranked by the stat column, so it captures coordinated, subtle shifts that a hard cutoff would miss. In gsea_stats_<contrast>.csv, padj < 0.05 is significant, and the sign of NES gives the direction: positive means the pathway is up in condition A.

gprofiler_output/

gprofiler2 tests the significant gene lists from the DESeq2 results, separately for up- and down-regulated genes, writing gprofiler_UP_<contrast>.csv and the matching DOWN file. Key columns are term_name, source (GO:BP/MF/CC, KEGG, REACTOME), p_value (already corrected by g:SCS) and intersection_size.

The two answer different questions

GSEA uses the whole ranked list; gProfiler uses a thresholded list. Agreement between them strengthens a conclusion. A direction file is written only when something was enriched, so an absent _UP file means nothing passed, not that the step failed.

Splicing and isoforms #

rmats_output/

One subdirectory per condition pair, named <condition>_vs_REF to match the differential-expression tables, with REF as the denominator. rMATS reports five event types: SE (skipped exon), MXE (mutually exclusive exons), A3SS and A5SS (alternative 3' and 5' splice sites), and RI (retained intron). For each there is a *.MATS.JC.txt using junction counts only and a *.MATS.JCEC.txt adding reads on the exon body.

IncLevelDifference is the PSI difference and the effect size. In NaCl_vs_REF it is PSI(NaCl) minus PSI(REF), so a positive value means higher inclusion in NaCl: the same direction a positive log2FoldChange means in the DE table beside it. PSI is a proportion, so the difference is bounded at plus or minus 1. A value of 0.2 means twenty percentage points of the transcript pool shifted. It is not a fold change and should not be compared to one. A common cutoff is FDR < 0.05 with |IncLevelDifference| > 0.1.

The sign convention changed after v1.5.1

Directories were previously named REF_vs_<condition> and IncLevelDifference carried the opposite sign, the reverse of what a positive log2FoldChange meant in the DE tables beside it. Splicing results produced before this change point the other way, and the files give no indication of which convention they follow beyond the directory name. Do not compare results across that boundary without checking.

summary.txt uses different criteria

rMATS builds it with an |IncLevelDifference| cutoff of zero, so its SignificantEvents columns count every FDR-significant event regardless of effect size. Those numbers will be larger, often much larger, than the cutoff above produces. Recompute from the *.MATS.JC.txt files rather than quoting summary.txt.

dtu_output/ and diffsplice_output/

DEXSeq tests whether the proportions of a gene's transcript isoforms shift between conditions. Use dtu_gene_qvalues.csv with gene_qvalue < 0.05 to call genes, then dtu_transcript_results.csv to see which transcripts drive the switch. edgeR's diffSpliceDGE tests whether each feature's fold change departs from its gene's overall fold change, the feature being an exon for STAR and HISAT2 and a transcript for Salmon and Kallisto. Use diffsplice_gene_results.csv with FDR < 0.05, then the per-feature table.

Both draw their ten most significant genes as PNG and SVG, and both carry a reproduce/ folder. DTU writes them beside its tables as <rank>_dtu_plot_<gene>_aka_<gene_name>: a bar per condition per transcript at that condition's mean isoform fraction, every sample drawn as a point on top, and transcripts at padj < 0.05 starred in red. diffSplice puts its plotSpliceDGE figures in a <condition>_vs_REF/ subdirectory per contrast, each showing every feature's log fold change against the gene's own, with features at FDR < 0.05 marked in red and sized by how far below.

isoform_switch_output/

A switch is a gene where the dominant transcript isoform changes between conditions even if total gene expression does not: biologically important and invisible to gene-level DE. Sort isoform_switches.csv by gene_switch_q_value; it holds the top 50. switchList_analyzed.rds holds the whole switchAnalyzeRlist, for consequence prediction, ORF analysis or plotting other genes.

Figures go in one <condition>_vs_REF/ subdirectory per condition pair, ten per pair as PNG and SVG, ranked from 1 and zero-padded so the folder sorts by significance: 01_switch_plot_ENSG00000168710_aka_AHCYL1.svg and so on. Each shows isoform usage, isoform expression, gene expression and transcript structure for one gene. A reproduce/ folder redraws any of them.

The effect size is dIF, the change in isoform fraction, computed as IF(condition_2) minus IF(condition_1). The baseline goes in condition_1, so in TGFb_vs_REF a positive dIF means that isoform takes a larger share of its gene's expression in TGFb: the same direction a positive log2FoldChange means in the DE tables beside it.

The three tables do not join on gene_id

isoform_switches.csv carries versioned gene IDs (ENSG00000168710.20), because IsoformSwitchAnalyzeR keeps the Ensembl version on gene_id while dtu_output/ and diffsplice_output/ read it bare from the GTF. Joining the three on gene_id matches nothing. The figure names and reproduce/switch_plot_genes.csv.gz use the bare form, and that table carries both.

Three independent views of splicing

rMATS classifies splicing events, DEXSeq DTU tests transcript proportions, and edgeR diffSplice tests each feature's fold change against its gene. IsoformSwitchAnalyzeR adds which switch happened and its functional consequence. They answer related but distinct questions, and agreement between them is informative.

Gene fusions #

star_fusion/<sample>.star-fusion.fusion_predictions.tsv and its .abridged.tsv summary. Higher JunctionReadCount plus SpanningFragCount support, and YES in LargeAnchorSupport, indicate more confident calls. FFPM is fusion fragments per million, normalised for depth. Always validate fusion candidates against known biology and, ideally, orthogonal evidence.

The two reports #

multiqc/rnaseq-flow_multiqc_report.html is a single interactive page combining FastQC, fastp, alignment, RSeQC and featureCounts metrics for every sample. It is the best starting point for a run-wide quality overview and for spotting outlier samples. Samples appear by samplesheet id, with a Source FASTQ column mapping each back to the file it came from.

quarto_report/analysis_report.html brings the run together in one document. It opens with a Run overview read from run_manifest.json (what ran it, what went in, the library layout, the aligner, the baseline, and the reference set with its source and release), a Sample design table, and a "Requested but not performed" notice that renders only when an analysis was asked for and skipped. Then the results: a MultiQC summary, per-contrast significant-gene counts, a shrinkage before-and-after view, interactive plotly volcano and MA plots for both callers, PCA, MDS and the top-variable-gene heatmap, a DESeq2-against-edgeR agreement table, searchable result tables, a GSEA dot plot and a gProfiler Manhattan plot. Sections for stages that did not run are omitted.

Its Alternative splicing section reads rmats_output/ directly: an events-per-type count recomputed from the MATS.JC.txt files rather than taken from summary.txt, a JC-against-JCEC agreement table, a PSI-difference volcano coloured by event type, per-replicate PSI for the top 16 events, and a searchable table. It ends by counting the genes whose splicing changed while their total expression did not, which the DE tables miss by construction.

Three further sections render when their analysis ran: Differential transcript usage for --dtu, Differential splicing for --diffsplice at whichever level the aligner produced, and Isoform switching for --isoform_switch. Each gives the significant genes, a searchable table and that analysis's per-gene figures embedded inline. All three can run, succeed and legitimately produce nothing, so each says so in words rather than showing an empty table. The yeast example does exactly that: Ensembl R64-1-1 has 7127 genes and 7127 transcripts, so no gene has the two or more isoforms these tests need.

Redrawing figures #

Every figure can be redrawn, and adapted, from the results directory alone: no rerunning, no access to the original compute, no digging through work/. Each of deseq2_output/, edger_output/, gsea_output/, gprofiler_output/, isoform_switch_output/, dtu_output/ and diffsplice_output/ carries a reproduce/ subfolder with a standalone R script per figure type, gzipped copies of the tables behind each figure, and only the R objects a plot genuinely needs.

The split is that the parent folder is for reading and reproduce/ is for running. Parent CSVs stay uncompressed so they open by double-click; the reproduce/ copies are gzipped, which R reads transparently.

cd results/deseq2_output/reproduce
Rscript volcano.R

The scripts are written to be changed, not merely run. Contrast, cutoffs, colours and dimensions are named constants in the first lines, so adjusting a legend does not mean reading a ggplot chain:

CONTRAST      <- "NaCl_vs_REF"
PADJ_CUT      <- 0.05
LFC_CUT       <- 1
WIDTH         <- 8
HEIGHT        <- 6.5
FIG_RES       <- 300
OUTPUT_PREFIX <- "repro_"

Regenerated figures are prefixed repro_ and get a matching .info.txt recording the settings used, the environment that produced them and where they came from, so a regenerated figure is never mistaken for the pipeline's own once it leaves the folder. rmats_output/ and star_fusion/ have no reproduce/ folder, because neither step produces a figure: rMATS and STAR-Fusion emit tables only.

Interpretation checklist #

  • MultiQC: no outlier samples, adapter content low after trimming
  • Alignment: uniquely-mapped rate acceptable for your organism
  • RSeQC: measured strandedness matches --strandedness
  • PCA and MDS: replicates cluster by condition
  • DE: genes significant in both DESeq2 and edgeR are the high-confidence set
  • Enrichment: GSEA and gProfiler tell a consistent biological story

Known limitations

  • Differential expression is gene-level by default. A transcript-level DTU test using DEXSeq is available opt-in via --dtu for the Salmon and Kallisto routes.
  • The tximport DE path requires --gtf so a transcript-to-gene map can be built. Without it, DE is skipped for Salmon and Kallisto.
  • The Ensembl reference downloader scrapes the Ensembl FTP listing. For unusual species, download references manually and pass them directly.
  • --ctat_lib must point at an already-extracted CTAT genome library directory, since the pipeline does not untar archives.

Citing a run

Cite only the tools that actually ran for your analysis, which depends on --aligner and the optional flags you set. The exact version of every tool used is recorded in pipeline_info/software_versions_mqc.yml. CITATIONS.md carries the publication for each and a methods paragraph to adapt.
